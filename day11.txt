  Answers to Research Questions

  Q1: Does DeepFilterNet change VAD quality?
  Yes. Using DFN for VAD degraded the F1 score from 80.7% to 77.4%. While it slightly reduced False Alarms, it significantly increased
  the Miss Rate (from 23% to 30%) because the denoiser pruned quiet human speech alongside noise.

  Q2: Does DeepFilterNet change grounding boundaries?
  Yes, drastically. The normalized grounding had 41 continuous segments. The DFN grounding shattered into 70 disconnected segments. The
  denoiser zeroed out natural speech pauses, causing the VAD to constantly interrupt and fragment the timeline.

  Q3: Does DeepFilterNet intrinsically hurt WhisperX?
  Yes, unequivocally. Pipeline 11C proves this. In 11C, the VAD, Grounding, and Diarization are identical to 11A. Only the audio sent to
  WhisperX was changed to DFN. 
   * WER degraded from 32.4% to 37.8%.
   * Deletions more than doubled (from 46 to 93).
  This proves DFN actively destroys the acoustic features WhisperX uses to transcribe speech, causing it to 'miss' words that are
  clearly present in the noisy normalized audio.

  Q4: Does DeepFilterNet improve final conversational intelligence?
  No. Across the prioritized metrics (cpWER, SA-WER, WDER), DFN caused severe degradation. The control pipeline (11A) achieved a cpWER
  of 50.3%, while the best DFN attempt (11C) could only reach 53.0%.

  Conclusion
  The degradation caused by DeepFilterNet is an intrinsic flaw when used prior to Transformer-based ASR like WhisperX on BWC audio.
  DeepFilterNet 'eats' the trailing consonants and low-volume words, causing massive catastrophic deletions regardless of how perfectly
  you align the VAD segments. Future optimization efforts must rely exclusively on normalization rather than aggressive neural
  denoising.

✦ The diagnostics directory is a special folder created during Phase 11 to provide concrete, file-based evidence for the errors that our
  metrics are reporting. Instead of just seeing a WER of "37%", you can go into this directory and see the exact segments or listen to
  the audio clips where those errors occurred.

  How is it generated?
  The experiments/phase11_dfn_ablation/step4_evaluate.py script is responsible for creating and populating this directory. It runs after
  all the pipelines have produced their final JSON outputs.

   1. VAD Diagnostics: The evaluate_vad function inside step4_evaluate.py compares the ground truth speech regions to the predicted VAD
      segments (from 11A_grounding.json and 11B_grounding.json) on a frame-by-frame basis. It then writes a JSON file listing the start
      and end times of every "miss" and "false alarm."
   2. ASR Diagnostics: The export_asr_errors function simply dumps the final JSON output of each pipeline. This provides a simple way to
      review the transcribed segments and their timestamps for context around ASR errors.
   3. Diarization Diagnostics: The script calls the pre-existing analyze_diarization_errors.py utility. This powerful script compares
      the speaker labels in the ground truth against the pipeline's output. For every region of Miss, False Alarm, or Confusion, it:
       * Logs the timestamp of the error.
       * Extracts a small .wav file of the audio around that error (±2 seconds) so you can listen to the mistake.

  What does it store?

  The directory is broken down by error type:

  1. diagnostics/vad_errors/
  This contains JSON files that tell you exactly when the Voice Activity Detection made a mistake.

   * 11A_vad_errors.json:
       * "miss": A list of timestamps where the ground truth had speech, but the VAD from normalized audio predicted silence.
       * "false_alarm": A list of timestamps where there was no speech, but the VAD detected something.
   * 11B_vad_errors.json: Same as above, but for the VAD run on the DeepFilterNet audio.

  2. diagnostics/asr_errors/
  This provides the full transcribed output for each pipeline, which serves as a reference for ASR errors.

   * 11A_asr_segments.json: A JSON file containing every transcribed segment from the control pipeline (11A). If the WER report shows a
     substitution, you can find the corresponding segment here to see the full sentence context.
   * 11B_asr_segments.json: Same, for pipeline 11B.
   * 11C_asr_segments.json: Same, for pipeline 11C.

  3. diagnostics/diarization_errors/
  This is the most detailed part, containing sub-folders for each pipeline.

   * 11A/:
       * diarization_errors.csv: A spreadsheet listing every single diarization error from pipeline 11A.
       * error_001_MISS_3.75_3.79.wav: An audio clip of a "Miss" error, where the diarizer failed to assign a speaker to a speech
         segment.
       * error_002_CONFUSION_10.11_12.45.wav: An audio clip of a "Confusion" error, where speech from "Speaker 1" was incorrectly
         assigned to "Speaker 2".
   * 11B/ and 11C/: Contain the same structure of .csv and .wav files for their respective pipelines.

---

✦ The diagnostics directory is a special folder created during Phase 11 to provide concrete, file-based evidence for the errors that our
  metrics are reporting. Instead of just seeing a WER of "37%", you can go into this directory and see the exact segments or listen to
  the audio clips where those errors occurred.

  How is it generated?
  The experiments/phase11_dfn_ablation/step4_evaluate.py script is responsible for creating and populating this directory. It runs after
  all the pipelines have produced their final JSON outputs.

   1. VAD Diagnostics: The evaluate_vad function inside step4_evaluate.py compares the ground truth speech regions to the predicted VAD
      segments (from 11A_grounding.json and 11B_grounding.json) on a frame-by-frame basis. It then writes a JSON file listing the start
      and end times of every "miss" and "false alarm."
   2. ASR Diagnostics: The export_asr_errors function simply dumps the final JSON output of each pipeline. This provides a simple way to
      review the transcribed segments and their timestamps for context around ASR errors.
   3. Diarization Diagnostics: The script calls the pre-existing analyze_diarization_errors.py utility. This powerful script compares
      the speaker labels in the ground truth against the pipeline's output. For every region of Miss, False Alarm, or Confusion, it:
       * Logs the timestamp of the error.
       * Extracts a small .wav file of the audio around that error (±2 seconds) so you can listen to the mistake.

  What does it store?

  The directory is broken down by error type:

  1. diagnostics/vad_errors/
  This contains JSON files that tell you exactly when the Voice Activity Detection made a mistake.

   * 11A_vad_errors.json:
       * "miss": A list of timestamps where the ground truth had speech, but the VAD from normalized audio predicted silence.
       * "false_alarm": A list of timestamps where there was no speech, but the VAD detected something.
   * 11B_vad_errors.json: Same as above, but for the VAD run on the DeepFilterNet audio.

  2. diagnostics/asr_errors/
  This provides the full transcribed output for each pipeline, which serves as a reference for ASR errors.

   * 11A_asr_segments.json: A JSON file containing every transcribed segment from the control pipeline (11A). If the WER report shows a
     substitution, you can find the corresponding segment here to see the full sentence context.
   * 11B_asr_segments.json: Same, for pipeline 11B.
   * 11C_asr_segments.json: Same, for pipeline 11C.

  3. diagnostics/diarization_errors/
  This is the most detailed part, containing sub-folders for each pipeline.

   * 11A/:
       * diarization_errors.csv: A spreadsheet listing every single diarization error from pipeline 11A.
       * error_001_MISS_3.75_3.79.wav: An audio clip of a "Miss" error, where the diarizer failed to assign a speaker to a speech
         segment.
       * error_002_CONFUSION_10.11_12.45.wav: An audio clip of a "Confusion" error, where speech from "Speaker 1" was incorrectly
         assigned to "Speaker 2".
   * 11B/ and 11C/: Contain the same structure of .csv and .wav files for their respective pipelines.
