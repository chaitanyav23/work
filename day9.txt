
  Overview of experiments/ Structure
  The directory contains three sub-packages and an __init__.py:
   - phase1_vad/: Benchmark of Voice Activity Detection models.
   - phase2_enhancement/: Benchmark of audio denoising and enhancement models.
   - phase3_diarization/: Comparative study of advanced diarization architectures.

  ---

  Phase 1: VAD Benchmarking (experiments/phase1_vad/)

  Objective: Determine if the high Miss Rate and False Alarm Rate observed in early tests were caused by the VAD model. It compares
  Silero VAD (baseline) against Pyannote VAD.

  Scripts and Logic:
   * pipeline_vad_silero.py:
       * Input: raw_audio/*.wav.
       * Logic: Uses Silero VAD to detect speech. It implements a "min-cut" strategy: if a detected segment is too long (e.g., >30s), it
         searches for the point with the lowest speech probability within that window to "cut" it. It then merges segments to create
         ~28s "grounding" chunks suitable for Whisper.
       * Output: experiments/phase1_vad/grounding_silero/{stem}_grounding.json.
   * pipeline_vad_pyannote.py:
       * Input: raw_audio/*.wav.
       * Logic: Uses Pyannote's segmentation-3.0 model. Similar to the Silero script, it merges the raw detections into ~28s grounding
         blocks.
       * Output: experiments/phase1_vad/grounding_pyannote/{stem}_grounding.json.
   * run_phase1.py:
       * Orchestration: Runs both VAD scripts, then executes the main hardened pipeline (run_final_hardened_pipeline.py) using those
         groundings, and finally triggers evaluation.
   * generate_report.py:
       * Logic: Scrapes CSV results from reports/ and generates a Markdown summary (reports/phase1_report.md) comparing DER (Diarization
         Error Rate) and Miss Rates.

  ---

  Phase 2: Speech Enhancement (experiments/phase2_enhancement/)

  Objective: Reduce Word Error Rate (WER) by cleaning up low-SNR (Signal-to-Noise Ratio) audio before it reaches the ASR engine.

  Scripts and Logic:
   * pipeline_enhancement_deepfilternet.py:
       * Input: raw_audio/*.wav.
       * Logic: Wraps the DeepFilterNet3 module to perform deep-learning-based noise suppression.
       * Output: Enhanced audio in experiments/phase2_enhancement/audio_deepfilternet/.
   * pipeline_enhancement_speechbrain.py:
       * Input: raw_audio/*.wav.
       * Logic: Implements SpeechBrain's MetricGAN+ (SpectralMaskEnhancement) model for dereverberation and noise reduction.
       * Output: Enhanced audio in experiments/phase2_enhancement/audio_speechbrain/.
   * run_phase2.py:
       * Orchestration: Runs enhancement, then runs VAD on the enhanced audio, and finally processes the enhanced audio through the full
         ASR pipeline.
   * generate_report.py:
       * Logic: Compares enhanced results against the Phase 1 baseline. (Note: Initial findings suggested that enhancement artifacts
         actually increased WER for Whisper).

  ---

  Phase 3: Diarization Study (experiments/phase3_diarization/)

  Objective: Move beyond standard diarization by testing NVIDIA NeMo's MSDD (Multi-scale Diarization Decoder) against Pyannote 3.1.

  Scripts and Logic:
   * pipeline_msdd.py:
       * Input: raw_audio/*.wav.
       * Logic: Configures a NeMo NeuralDiarizer using titanet_large for speaker embeddings and diar_msdd_telephonic for the multi-scale
         decoder. It outputs RTTM files which are converted to JSON.
       * Output: experiments/phase3_diarization/outputs_msdd/{stem}_diarization.json.
   * run_hardened_with_custom_diar.py:
       * Input: raw_audio/*.wav, VAD grounding, and the Custom Diarization JSON (e.g., from MSDD).
       * Logic: This is a specialized version of the pipeline. It performs ASR, then uses WhisperX's alignment model to map words to the
         precise timestamps provided by the custom diarization file rather than using Pyannote.
       * Output: Final transcripts in experiments/phase3_diarization/outputs_msdd_final/.
   * run_phase3.py:
       * Orchestration: Coordinates the generation of MSDD diarization, the Pyannote 3.1 baseline run, and the evaluation of both to
         determine the "best-in-class" diarizer for BWC.

  Summary of Output Locations
   * Grounding (Segments): experiments/phase[X]/grounding_[model]/
   * Processed Transcripts: experiments/phase[X]/outputs_[model]/
   * Enhanced Audio: experiments/phase2/audio_[model]/
   * Consolidated Reports: reports/phase[X]_report.md

  difficult Body-Worn Camera (BWC) audio.

  2. Detailed Comparison & Analysis

  Phase 1: Voice Activity Detection (The "Grounding" Problem)
   * Data Analysis:
       * Silero: WER 30.37%, DER 42.34%, Miss 17.84%, FA 17.46%.
       * Pyannote: WER 30.79%, DER 41.47%, Miss 11.64%, FA 22.99%.
   * Observation: Pyannote is significantly more "aggressive." While it produces more False Alarms (detecting speech where there is
     none), it successfully captures 6.2% more actual speech.
   * Analysis: In a grounded ASR pipeline (where VAD determines what the ASR "sees"), a False Alarm is a "cheap" error because Whisper
     can usually transcribe the silence as empty text. However, a Miss is a "fatal" error because that speech is permanently lost to the
     pipeline.

  Phase 2: Speech Enhancement (The "Artifact" Problem)
   * Data Analysis:
       * Baseline (Raw): WER 30.37%.
       * SpeechBrain (MetricGAN+): WER 45.04%.
   * Observation: Neural enhancement caused a massive 14.67% increase in Word Error Rate.
   * Analysis: Modern transformer-based ASR models like Whisper are trained on "real-world" noisy data. The "warbling" artifacts and
     phase distortions introduced by MetricGAN+ are mathematically more confusing to the transformer's attention mechanism than the
     original static environmental noise.

  Phase 3: Diarization (The "Attribution" Problem)
   * Observation: Even with optimized VAD, Diarization Error Rate (DER) remains the highest error category (often >40% on BWC). 
   * Analysis: The bottleneck has shifted from "hearing" the words to "assigning" them. BWC audio suffers from "moving speaker"
     syndrome—where the distance between the mic and the speaker changes constantly, causing the acoustic embedding to "drift" and split
     a single speaker into multiple clusters.

  ---

  3. Advanced Observations & Technical Inferences

   1. The "Loudness vs. Clarity" Paradox: Results show that Loudness Normalization (Pipeline B/C) provided more benefit than Denoising.
      By stabilizing the peak amplitude to -20dB, the speaker embedding models (used in Diarization) became more consistent, even if the
      background noise remained high.
   2. Substitution Dominance: In the BWC dataset, "Substitutions" (wrong words) are higher than "Deletions" or "Insertions." This infers
      that the problem isn't that Whisper can't hear the speaker (SNR), but that the audio quality is poor enough that it "guesses" the
      wrong phonemes (Low Clarity).
   3. VAD Coverage is Safety: The experiment proves that for forensic or compliance audio (like BWC), a high-recall VAD is preferable to
      a high-precision one. It is better to process 20% "junk" audio than to lose 5% of critical dialogue.

  ---

  4. Insights & Strategic Conclusions

   * Insight 1: Stop Enhancing, Start Normalizing. Conventional "Black Box" enhancement modules are detrimental to the current
     generation of ASR. The pipeline should prioritize simple signal processing (Bandpass filters, Normalization) over complex neural
     GANs.
   * Insight 2: The VAD-ASR Coupling. VAD is not just a pre-processing step; it is the "Context Generator." Because Whisper's
     performance is tied to the 30-second window context, the "Grounding" logic (how we merge VAD segments) is as important as the VAD
     model itself.
   * Insight 3: The Diarization Ceiling. We have reached the limits of "Offline Clustering." To further reduce DER, the project must
     move toward Overlap-Aware Neural Diarization (like NeMo MSDD) which uses the transcript text itself to help resolve speaker
     identities.

  Final Recommendation
  The project should adopt the "Aggressive Coverage" strategy:
   1. Use Pyannote 3.1 VAD for maximum speech capture.
   2. Apply Peak Normalization only.
   3. Disable Neural Enhancement (MetricGAN+).
   4. Implement Text-Informed Diarization to resolve the remaining speaker confusion.

These scripts form the backbone of the project's experimental framework and its final production logic. Below is a detailed breakdown
  of each.

  ---

  1. run_phase1.py (VAD Benchmarking)
  Purpose: To compare different Voice Activity Detection (VAD) models and determine which one provides the best "grounding" for ASR.

   * Input: 
       * raw_audio/: WAV files.
       * --skip-vad (Flag): Optional to skip the generation phase and only re-run evaluation.
   * Logic & Implementation:
       1. Generation: Iterates through silero and pyannote. It calls the respective pipeline_vad_[model].py scripts to generate
          "grounding" JSON files (segment timestamps).
       2. Pipeline Execution: For each VAD type, it runs the run_final_hardened_pipeline.py. It passes the specific grounding directory
          (e.g., experiments/phase1_vad/grounding_silero) to the pipeline.
       3. Evaluation: Calls evaluate_conversational_timeline.py to compare the generated transcripts against ground truth, specifically
          looking at DER and Miss Rates.
   * Output:
       * experiments/phase1_vad/grounding_[model]/: Timestamp segments.
       * experiments/phase1_vad/outputs_[model]/: Final transcripts for that VAD.
       * reports/conversational_eval_phase1_[model].csv: Performance metrics.

  ---

  2. run_phase2.py (Enhancement Benchmarking)
  Purpose: To test if pre-processing audio with neural enhancement models improves Whisper's transcription accuracy.

   * Input: 
       * raw_audio/: WAV files.
       * --skip-enhance (Flag): Skips the actual audio denoising step.
   * Logic & Implementation:
       1. Enhancement: Runs pipeline_enhancement_[model].py (DeepFilterNet or SpeechBrain) to create cleaned WAV files.
       2. VAD Stage: Because the audio signal has changed, it runs a fresh VAD pass (custom_pipeline_stage1_vad.py) on the enhanced
          audio.
       3. Full Pipeline: Runs run_final_hardened_pipeline.py using the enhanced audio and new VAD groundings.
       4. Evaluation: Compares metrics to see if the enhancement reduced Word Error Rate (WER).
   * Output:
       * experiments/phase2_enhancement/audio_[model]/: The "cleaned" WAV files.
       * experiments/phase2_enhancement/outputs_[model]/: Transcripts from enhanced audio.

  ---

  3. run_phase3.py (Diarization Benchmarking)
  Purpose: To compare the default Pyannote 3.1 clustering against advanced neural diarization (NVIDIA NeMo MSDD).

   * Input:
       * raw_audio/: WAV files.
       * vad_custom_grounding/: Pre-existing "best" VAD segments.
   * Logic & Implementation:
       1. NeMo MSDD: Runs pipeline_msdd.py. Unlike Pyannote, NeMo requires a manifest file and a complex config (TitaNet embeddings +
          MSDD decoder).
       2. Baseline: Runs the hardened pipeline with standard Pyannote 3.1 diarization.
       3. Custom Merge: Runs run_hardened_with_custom_diar.py. This script is unique because it tells the pipeline: "Don't run your own
          diarizer; use this MSDD JSON file I just generated."
       4. Evaluation: Specifically evaluates Speaker Attribution accuracy.
   * Output:
       * experiments/phase3_diarization/outputs_msdd/: Raw speaker segments from NeMo.
       * experiments/phase3_diarization/outputs_msdd_final/: Transcripts with NeMo speaker tags.

  ---

  4. run_final_hardened_pipeline.py (The Production Core)
  Purpose: This is the "Gold Standard" pipeline resulting from all experiments. It is designed to be "hardened"—meaning it is resistant
  to the noise and long-form drifting common in BWC.

   * Inputs:
       * --audio-dir: Path to WAVs.
       * --grounding-dir: Path to VAD JSONs (this is the "Grounded" part—it only transcribes where it knows there is speech).
       * HF_TOKEN: Required to pull Pyannote 3.1 models.
   * Logic & Implementation:
       1. Phase 1: Load: Loads WhisperX large-v3 (ASR) and Pyannote 3.1 (Diarization).
       2. Phase 2: The "Muting" Trick: This is a critical innovation. It creates a mask based on the VAD segments. Any audio not in a
          VAD segment is zeroed out (muted). This ensures the Diarizer doesn't waste clusters on wind noise or sirens, which drastically
          reduces "False Alarm" speaker segments.
       3. Phase 3: Hardened ASR: Instead of transcribing the whole file, it loops through each VAD segment and transcribes it as a
          manual slice. It sets condition_on_previous_text=False to prevent the "hallucination loops" common in Whisper when dealing
          with noisy audio.
       4. Phase 4: Alignment & Merge: Uses WhisperX phoneme alignment to get exact word-level timestamps, then assigns speakers from the
          Diarization results to each word.
   * Output:
       * {stem}_hardened.json: Full machine-readable data (word timestamps, speakers, etc.).
       * {stem}_hardened.txt: A clean, human-readable transcript with [Timestamp] Speaker: Text formatting.

  ---

  Summary of the "Hardened" Philosophy
  The "Hardened" pipeline is defined by Isolation:
   * Isolation of Space: Muting non-speech so the Diarizer only sees humans.
   * Isolation of Time: Slicing audio into chunks so Whisper's attention mechanism doesn't drift.
   * Isolation of Identity: Using grounded segments to prevent "Ghost Speakers" from being created by background noise.
