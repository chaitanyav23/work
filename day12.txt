# Phase 13 — Karen End-to-End Generalization Benchmark

## Objective

Phase 13 is NOT an optimization experiment.

Phase 13 is a true out-of-distribution evaluation of the current best validated conversational intelligence pipeline (Phase 10C / Phase 11A architecture) on a completely new recording:

```text
raw_audio/karen.mp3
```

using:

```text
ground_truth/karen.txt
```

for evaluation only.

The goal is to determine:

1. How well the BWC-optimized pipeline generalizes to unseen conversational audio.
2. Whether MSDD can discover speakers without any speaker-count prior.
3. Whether the current bottleneck remains ASR, diarization, attribution, fusion, or overlap.
4. How the Karen dataset compares to the BWC benchmark.

No information from the ground truth may be used during inference.

Ground truth must remain evaluation-only.

# Step 1 — Audio Preparation

Input:

```text
raw_audio/karen.mp3
```

Convert to:

```text
audio/karen_normalized.wav
```

using:

```bash
ffmpeg -i raw_audio/karen.mp3 \
-af loudnorm=I=-20:TP=-1.5:LRA=11 \
-ar 16000 \
-ac 1 \
audio/karen_normalized.wav \
-y
```

Generate an audio audit report:

```text
reports/audio_audit.csv
```

including:

* Duration
* Sample Rate
* LUFS
* RMS
* Peak
* Spectral Centroid
* Spectral Roll-off

```text

```



# Step 4 — WhisperX

Use:

```python
language="en"
```

Do not use auto language detection.

Use:

```text
WhisperX Large-v3
```

For each VAD segment:

1. Slice audio.
2. Transcribe.
3. Align with wav2vec2.

Generate:

```text
outputs/aligned_words.json
```

containing:

* word
* start
* end

# Step 5 — MSDD


```python
oracle_vad = True

```

Requirements:

* Do NOT use ground truth.
* Do NOT use speaker count from ground truth.
* Do NOT hardcode number of speakers.
* MSDD must discover speakers automatically.

Generate:

```text

```

and report:

```text
Discovered Speaker Count
```

# Step 6 — Fusion

Use the validated fusion implementation.

```text

```
